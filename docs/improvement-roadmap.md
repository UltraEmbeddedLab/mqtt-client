# php-iot Improvement Roadmap

**Scope:** 8 specialist audits, adversarially verified, deduplicated to ~60 distinct defects across 8 themes. Baseline: PHPStan max = 0 errors, Pint clean, 231 tests green, type coverage 96.5%. All of the below ships green today — that is the central fact of this report.

## Theme 1 — Stream integrity: there is no read buffer, so a timeout is unrecoverable

**Thesis:** `loopOnce()` reads a frame in 3–6 separate socket calls with no buffer behind them, so any interruption mid-frame discards consumed bytes permanently and the client parses payload as headers for the rest of the connection.

| #   | Defect                                                                                                                                                                                                                                                                                                                                                                               | Why it matters                                                                                                                                                                                                                                                                                                                                             | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1.1 | **Per-read timeout + unguarded framing reads.** `src/Client/Client.php:730` reads the type byte inside `try/catch (Timeout                                                                                                                                                                                                                                                           | TransportError)`; the Remaining-Length varint loop at `:746` and the body read at `:755` are **outside** it, and each restarts a fresh `$timeoutSec` deadline. `TcpTransport::readExact` (`src/Transport/TcpTransport.php:96-163`) accumulates into a local `$data` and throws it away on deadline expiry.                                                 | A 200 KB retained PUBLISH on a link slower than `loopOnce(0.2)` throws `Timeout` straight out of `run()`/`messages()`/`publish()`. If the caller catches and continues, the socket is positioned mid-body: the next byte is decoded as a fixed header, an arbitrary Remaining Length is decoded, and every frame boundary is wrong for the life of the connection. `isOpen()` still returns true, so auto-reconnect never fires. Reproduced empirically (0.108 s to `Timeout` on the second 1-byte read). Also: `loopOnce(30.0)` can block for 6×30 s, so the timeout argument bounds nothing. | **Interim:** one deadline computed at the top of `loopOnce()`, all three reads inside the same try/catch, and `transport->close()` on any mid-frame failure. **Real fix:** `Protocol\PacketReader` owning a persistent string buffer + `tryReadFrame(): ?RawFrame`; `loopOnce()` blocks only on readability, never on a byte count. Also interacts badly with Nagle/delayed-ACK.                                                                                                                                                                            | Same change as 1.1 — buffered reader.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## Theme 2 — Silent data loss: messages the broker considers delivered are dropped

**Thesis:** Four independent paths discard or misreport messages with no exception, no warning, and in three cases after the broker has already been acknowledged.

| # | Defect | Why it matters | Fix |
|---|---|---|---|
| 2.1 | **CRITICAL — `array_shift()` on the packet-ID-keyed QoS 1 dedup map.** `src/Client/Client.php:784`: `if (count($this->qos1Seen) > $this->qos1SeenMax) { array_shift($this->qos1Seen); }` where `qos1Seen` is `array<int packetId, float>` (`:110`). `array_shift` **renumbers integer keys from 0**. Verified: `[500=>1,501=>1,502=>1]` → keys `[0,1]`. Lookup at `:776` returns early, dropping the message — *after* the PUBACK was already written at `:770`. Reported independently by 5 of 8 dimensions. | On the 257th inbound QoS 1 message (default `qos1DeduplicationSize` = 256) the cache keys become the contiguous range 0..255, corresponding to nothing that was seen. From then on every inbound QoS 1 PUBLISH with an ID in 1..255 is PUBACKed and silently discarded — forever, since the reindex repeats on every eviction. `qos1Seen` is also absent from `resetConnectionState()` (`:374`), so after a reconnect (broker IDs restart at 1) the loss is near-total. Total, unrecoverable, silent violation of the exact guarantee the user selected QoS 1 for. | Immediate: `unset($this->qos1Seen[array_key_first($this->qos1Seen)])`. Structural: ID-keyed dedup is unsound in principle — IDs are reusable the instant PUBACK is sent (§2.2.1) and MQTT-3.3.1-3 says DUP is not evidence of a prior copy. Suppress only when `$msg->dup === true`, add time-based expiry, make it opt-in, clear it in `resetConnectionState()`. |
| 2.2 | **CRITICAL — the inbound queue is never drained in the `run()`/`onMessage()` path.** `src/Client/Client.php:1136` unconditionally `enqueue()`s and *then* invokes the handler (`:1145`). The only `dequeue()` calls are inside `awaitMessage()` (`:950/:965/:978`). `run()` (`:997`) sets the handler and loops on `loopOnce(0.2)` — it never calls `awaitMessage()`. | The library's own documented long-running pattern leaks every message forever. At 100 msg/s the `SplQueue` holds 360k `InboundMessage` objects (topic + payload + properties) after one hour; a gateway subscribed to `sensors/#` at 20 msg/s × 1 KB accumulates ~1.7 GB/day and is OOM-killed. A hostile broker turns it into a minutes-long kill. Conversely, registering `onMessage` *and* iterating `messages()` delivers everything twice. | In `deliverIfMatches()`: if a handler is registered, invoke and return — do not enqueue. Independently bound the queue via `Options::withInboundQueueSize()` with a drop counter. Regression test: pump 10k messages through `run()`, assert queue depth stays 0. |
| 2.3 | **Inbound MQTT 5 Topic Aliases are never resolved, although the client invites the broker to use them.** `Client::connect():243` sends `topic_alias_maximum` whenever `Options::$topicAliasMaximum > 0`. `V5\Decoder::decodePublish` parses `topic_alias` (`src/Protocol/V5/Decoder.php:420`) and returns the wire topic verbatim. The PUBLISH branch (`Client.php:766-811`) goes straight to `deliverIfMatches()`. `TopicAliasManager::registerAlias()`/`resolveAlias()` have **zero call sites in `src/`**. | Set `withTopicAliasMaximum(10)` against EMQX/HiveMQ/Mosquitto 2.x: the broker sends the first PUBLISH with the full topic + alias, then every subsequent one with `topic = ''` + alias. The application receives `InboundMessage(topic: '')` from message two onward. Topic-based routing breaks; with any `messageFilters` configured, `deliverIfMatches()` (`:1135`) drops them all. The user sees exactly one message per topic per connection — from turning on a documented, first-class bandwidth optimisation. | Before delivery: alias present + non-empty topic → `registerAlias()`; alias present + empty topic → `resolveAlias()`, rewrite `InboundMessage::$topic`, `ProtocolError` on unknown alias. Reject alias 0 or > advertised max → DISCONNECT 0x94 (MQTT-3.3.2-8). Reset the inbound map on every connection (§3.3.4). Use a **separate** inbound manager — see 5.7. |
| 2.4 | **Offline queue drain loses the message that fails and abandons the rest.** `Client.php:1278`: `while (($msg = $this->offlineQueue->dequeue()) !== null) { try { publish(...) } catch (Throwable) { warning; break; } }` — dequeued *before* the attempt, never re-queued. | Five buffered QoS 1 messages; #3 times out waiting for PUBACK on a still-recovering broker. #3 is permanently and silently lost; #4–5 wait for the next reconnect. `publish()` returned `0` when it was enqueued, indistinguishable from a successful QoS 0 send, so the caller cannot detect it. Worse: the drain runs synchronously inside `connect()` (`:333`), so 1000 queued QoS 1 messages × `ackTimeout` 5.0 × 3 resends can block a single `connect()` call for hours. | Peek, or re-enqueue at the head on failure; continue past per-message failures with a bounded retry. Move the drain out of `connect()` into `loopOnce()`, paced by the caller, and after resubscribe rather than before. |
| 2.5 | **`RequestResponse` swallows every non-matching message it dequeues.** `src/Client/RequestResponse.php:86`: `$msg = $this->client->awaitMessage($remaining);` — which *dequeues* — then `continue`s on a correlation mismatch. Never re-enqueued. Zero tests. | An app using both `messages()` and RPC loses every sensor message that arrives inside the request window. Loss proportional to request latency, no log, no metric. (Push-style handler consumers are unaffected — the handler fires at enqueue time.) | Route non-matching messages back, or implement correlation as a registry inside `Client` so it never competes with `awaitMessage()` for the queue. |
| 2.6 | **QoS 1 PUBACK is written before the handler runs, and handler exceptions are swallowed.** `Client.php:770-772` acks before dedup, before filtering, before `deliverIfMatches()` at `:788`. `:1143-1152` catches `Throwable` and logs. Same for QoS 2 (PUBCOMP at `:856`, delivery at `:865`). No manual-ack API exists. | A handler writing to Postgres during a 30 s outage: every message in the window is already acked, the broker will never resend, the exception is logged at error and discarded. The application contracted for at-least-once and got at-most-once. | `Options::$ackMode` (`Auto`/`Manual`); in Manual, `InboundMessage` carries an `ack()` handle and PUBACK/PUBCOMP is deferred. At minimum, ack after a successful handler invocation in Auto mode and re-raise or dispatch handler exceptions. |

## Theme 3 — Liveness: a client whose job is to hold a connection open cannot reliably hold one open

**Thesis:** Keepalive is driven by the wrong clock, has no failure detection, ignores the broker's override, and permanently disables itself after one reconnect — and when the connection does die, no API can tell you.

| # | Defect | Why it matters | Fix |
|---|---|---|---|
| 3.1 | **Keepalive is reset by *inbound* traffic.** `loopOnce()` calls `touchActivity()` (`Client.php:154`) after reading any packet (`:756`); `maybeAutoPing()` (`:174`) fires on `now - lastActivity >= keepAlive * 0.9`. | MQTT-3.1.2-23 obliges the **client** to *send* within the window; receiving does not count. A subscriber on a topic publishing once per second with `keepAlive = 60` never reaches the threshold, never sends PINGREQ, and is closed by the broker at 90 s — then flaps forever. This is the library's primary use case. | Split the clock: `lastSent` (updated only in `trackWrite()`) drives `maybeAutoPing()`; keep `lastReceived` for dead-peer detection. |
| 3.2 | **`pingOutstanding` latches: no PINGRESP timeout, and never reset across reconnects.** Set at `Client.php:170`, cleared only on inbound PINGRESP (`:815`), gated at `:184` by `! $this->pingOutstanding`. `resetConnectionState()` (`:374-382`) resets only `topicAliasManager` and `flowControl`. | (a) A NAT eviction or hard-killed broker VM black-holes the flow with the socket still "open": one PINGREQ goes out, no reply, and `maybeAutoPing()` is a no-op **forever**. `loopOnce()` returns false, `run()` spins on idleSleep, the app looks healthy and receives nothing indefinitely. Auto-reconnect never triggers because `isOpen()` is true. This is the single most common IoT field failure. (b) Even after a successful reconnect the flag stays true, so keepalive is dead for the life of the process and the client flaps every 1.5×keepAlive. | Record `pingSentAt`; if `pingOutstanding && now - pingSentAt > pingResponseTimeout`, close and let reconnect take over. Reset **every** connection-scoped field in `resetConnectionState()` (`pingOutstanding`, all four `last*Ack` slots, `qos2InboundPending`, `qos1Seen`, `lastActivity`, `inbound`) and call it at the **start** of `connect()`. Better: move it all into a per-connection object so forgetting is structurally impossible. |
| 3.3 | **CONNACK `server_keep_alive` is decoded and ignored.** `V5\Decoder` parses 0x13; `Client::connect()` (`:300-318`) reads only `assigned_client_identifier`, `topic_alias_maximum`, `receive_maximum`. `ConnAck::getServerKeepAlive()` (`src/Protocol/Packet/ConnAck.php:174`) has no callers. `Options` is immutable with nowhere to record a negotiated value. | MQTT-3.2.2-22 makes this a MUST. `withKeepAlive(300)` against EMQX with `server_keep_alive = 60`: the client pings at 270 s, the broker DISCONNECTs 0x8D at 90 s. With auto-reconnect on, an infinite 90-second connect/drop loop that never delivers anything. | Store `effectiveKeepAlive` on the client from `$connack->getServerKeepAlive() ?? $options->keepAlive`, read it in `maybeAutoPing()`, reset on reconnect, expose it on `ConnectResult`. |
| 3.4 | **`loopOnce()` swallows `TransportError` and returns `false` — identical to an idle poll.** `Client.php:733-739`. No `isConnected()`, no `state()`, no `ConnectionState` enum anywhere in the codebase; `ServerDisconnect` is dispatched only for a decoded DISCONNECT packet (`:913`). | With `autoReconnect` off (the default), a broker restart makes `run()` loop forever: closed transport → `TransportError` → `false` → usleep → repeat, at info level, permanently disconnected, with no API to detect it. `run()` never returns, no exception escapes, no event fires. A supervisor sees a live process and never restarts it. | Dispatch a `ConnectionLost` event; rethrow `TransportError` when auto-reconnect is disabled; add `ClientInterface::isConnected(): bool` and `state(): ConnectionState`. Never use one return value for "idle" and "gone". |
| 3.5 | **All deadlines use wall-clock `microtime()`.** Keepalive (`Client.php:154/180`), flow control (`:428`), QoS 1/2 (`:503/:546`), SUBACK (`:638`), UNSUBACK (`:688`), `awaitMessage` (`:973`), `RateLimiter::refill():90`, `FlowControl:67/111`, `TcpTransport:113`, `WsTransport:153/353/465`. `hrtime()` appears only in `benchmarks/`. | An NTP step of +45 s expires every outstanding deadline at once: an in-flight QoS 1 publish "times out", resends with DUP, exhausts `maxResendAttempts` and throws for a message the broker already acked. A −45 s step stalls keepalive past the broker's window. | A `Clock` collaborator over `hrtime(true)/1e9` for every interval and deadline; keep `time()` only for `SessionState::$savedAt`. Injecting it also makes all timing logic unit-testable without sleeping. |
| 3.6 | **Reconnect backoff sleeps inside `loopOnce()`.** `attemptReconnect()` (`:1058`) does `usleep(floor($delay * 1e6))` at `:1072`, then a blocking `connect()` (5.0 s CONNACK reads) plus a synchronous `subscribeWith()` per stored subscription (5 s each). Jitter is symmetric ±20%. | `loopOnce(0.01)` from a user's own loop can block for `reconnectMaxDelay` + 5 s + 5 s × subscription count — a minute with 20 subscriptions. Symmetric ±20% jitter does not decorrelate a fleet: 10k devices re-stampede a restarted broker within a narrow band. | Store `nextReconnectAt` and return immediately until it passes — never `usleep()` on a caller-timeout-bounded path. Use full jitter: `rand(0, min(max, base * 2**attempt))`. |
| 3.7 | **Reconnect re-enters the packet pump recursively.** `loopOnce():719` → `attemptReconnect():1058` → `connect()` → `drainOfflineQueue():333` → `publish()` → `loopOnce():528`. Each successful connect resets `reconnectAttempts = 0` (`:1081`), so `reconnectMaxAttempts` never caps it. | On a link flapping every few seconds the stack grows a frame per cycle until memory is exhausted, and messages are published before resubscribe completes (`:1086` runs *after* the drain), so request/response replies are missed. | `$inPump` reentrancy guard making nested `loopOnce()` a no-op; move `drainOfflineQueue()` out of `connect()` to after resubscribe. The sans-io split removes the class of problem — reconnect becomes a driver concern. |
| 3.8 | **TLS handshake failure discards the OpenSSL reason and leaves the socket open.** `TcpTransport.php:233`: `@stream_socket_enable_crypto(...)` then `throw new TransportError('TLS negotiation failed')` — no `openssl_error_string()`, no `close()`. Identical at `WsTransport.php:246`. `Client::connect():230` lets it propagate without closing. | The user cannot distinguish "certificate verify failed" from "unknown ca" from "wrong version number" (connected to the plaintext port). Worse with auto-reconnect: `attemptReconnect()` catches and returns false, but `loopOnce():719` checks `! isOpen()` — which is **false**, because the half-open socket is still there — so reconnect never retries and the client spins on reads over a failed handshake. | Drain `openssl_error_string()` + `error_get_last()` into the message; `$this->close()` before throwing. Wrap the whole connect sequence in try/catch that closes on any failure. |
| 3.9 | **`stop()` can be silently undone by an inbound DISCONNECT.** `Client.php:919-925` writes `shouldStop = false` when `autoReconnect` is on; `shouldStop` is the only exit condition for `run()` (`:1001`) and `messages()` (`:1016`). | SIGTERM handler calls `stop()` while `loopOnce()` is dispatching a server DISCONNECT (broker restarting — a common simultaneous event): the flag is cleared, `run()` keeps looping, the process never exits, the supervisor escalates to SIGKILL, skipping the graceful DISCONNECT and firing the Will. | Never write `false` to `shouldStop` from packet handling — use a separate `reconnectRequested` flag. Make `stop()` a latch only the caller can clear. |

## Theme 4 — Hostile-broker hardening: nothing on the receive path is bounded

**Thesis:** Five bytes kill the process; patience kills it more slowly; and the credentials are in the debug log.

| # | Defect | Why it matters | Fix |
|---|---|---|---|
| 4.1 | **HIGH — no maximum packet size anywhere on the receive path.** `Client.php:755`: `$rl = Bytes::decodeVarInt(...); $body = $this->trackRead($rl, $timeoutSec);` — `decodeVarInt` legitimately returns up to 268,435,455 and there is no ceiling. The same pattern is **pre-authentication** in `connect():290`. No `maximumPacketSize` on `Options`; `V5\Encoder::encodeConnect` (`:81-120`) emits only 0x11/0x21/0x22, never 0x27 — so per §3.1.2.11.4 the broker is explicitly entitled to send unlimited packets. | A hostile broker, a MITM on plaintext 1883, or a compromised shared broker answers CONNECT with `20 FF FF FF 7F` and stops. `fread($stream, 268435455)` allocates the full requested `zend_string`: instant fatal `Allowed memory size exhausted` at the default 128 M, or OOM-killer at `-1` (typical for CLI daemons). Five bytes, no credentials needed. Combined with 1.1, any payload containing `FF FF FF 7F` becomes the same weapon after a desync. | `Options::$maximumPacketSize` (default 1 MiB, hard cap 268435455); check **before** `trackRead` in both `loopOnce()` and `connect()`; v5 → DISCONNECT 0x95 and close. Emit property 0x27 in CONNECT. Defensive cap in `TransportInterface::readExact`. Test: feed `20 FF FF FF 7F` through a fake transport, assert `ProtocolError`. |
| 4.2 | **Unbounded inbound QoS 2 pending map, never cleared on reconnect.** `Client.php:801`: `$this->qos2InboundPending[$pid] = $msg;` holds full `InboundMessage` objects keyed by broker-chosen ID, freed only on matching PUBREL (`:861`). No count cap, no byte cap, no TTL, absent from `resetConnectionState()`. `Options::$receiveMaximum` is advertised in CONNECT (`:240`) but only ever applied to *outbound* FlowControl (`:316`) — the client lies to the broker about its own receive maximum. | 65,535 QoS 2 PUBLISHes with distinct IDs, 100 KB each, no PUBRELs → ~6.5 GB resident. Even 8 KB payloads pin 512 MB. Orphans accumulate across every reconnect. Trivially reachable by a malicious publisher or any broker that crashes mid-handshake. | Bound by count (`receiveMaximum`) **and** accumulated bytes; v5 → PUBREC 0x97 (Quota Exceeded) beyond it. TTL-expire entries. Clear in `resetConnectionState()`. Expose pending count as a metric. |
| 4.3 | **Malformed PUBLISH with QoS bits = 3 escapes as an uncaught `\ValueError`.** `src/Protocol/V311/Decoder.php:89` and `src/Protocol/V5/Decoder.php:290`: `$qos = QoS::from(($flags & 0x06) >> 1)`. Verified at runtime. `\ValueError` is outside `MqttException`. | A corrupting proxy, a broken bridge or a hostile peer kills a long-running daemon with an exception no documented handler catches. MQTT-3.3.1-4 requires this be treated as Malformed Packet with DISCONNECT 0x81. | `QoS::tryFrom($v) ?? throw new ProtocolError(...)` in both decoders. While there, enforce MQTT-2.2.1-2 (QoS>0 requires packetId ≠ 0), MQTT-3.3.1-2 (DUP=0 on QoS 0), MQTT-3.6.1-1 (PUBREL flags 0b0010). Have `loopOnce()` respond to `ProtocolError` on an inbound packet with DISCONNECT 0x81 + close. |
| 4.4 | **Credentials hex-dumped into the PSR-3 log.** `Client.php:260`: `$this->logger->debug('>> CONNECT', ['preview' => $this->hexPreview($data)])`; `hexPreview()` (`:1124`) hex-encodes the first 64 bytes. A v3.1.1 CONNECT with a 16-char clientId, 9-char username and 10-char password totals 53 bytes — comfortably inside the window. Repeated on every auto-reconnect (`:1080`). `Util\ConsoleLogger:23` has **no level threshold** and writes every level to STDERR. | CWE-532. Monolog at DEBUG on staging (or the shipped `ConsoleLogger` at any level) writes the broker password to the log file, the log shipper, and Sentry breadcrumbs. Recoverable with `xxd -r -p`. | Never hex-dump CONNECT — log `clientId`, `hasUsername`, `hasPassword`, `bytes`, `willTopic`. Gate raw previews behind `Options::withPacketTracing(true)` with redacted credential ranges. Add a level threshold to `ConsoleLogger`; mask `Options::$password` in `__debugInfo()`. |
| 4.5 | **TLS: no minimum version, no cipher policy, no pinning.** `TcpTransport.php:232` (and `WsTransport.php:245`) hard-code `STREAM_CRYPTO_METHOD_TLS_CLIENT` — verified = 121 on PHP 8.4.23 = TLSv1.0\|1.1\|1.2\|1.3. `TlsOptions` exposes no `crypto_method`, `ciphers`, `security_level`, `verify_depth`, or `peer_fingerprint`. | RFC 8996 says MUST NOT for TLS 1.0/1.1; PCI-DSS prohibits them. A compliance-bound user cannot adopt the library without patching it, and an IoT fleet that needs certificate pinning (AWS IoT / Azure IoT guidance) cannot express it at all. Paho, MQTTnet and rumqtt all default to 1.2+. | Default to `TLSv1_2_CLIENT|TLSv1_3_CLIENT`; add `TlsOptions::withMinimumVersion()`, `withCiphers()`, `withVerifyDepth()`, `withPeerFingerprint()`. # Verdict

## What this library already does well — specifically

**The binary layer is genuinely correct, and that is the hardest part to get right.** `Bytes::encodeVarInt`/`decodeVarInt` are correct at every boundary tested (0, 127, 128, 16383, 16384, 268435455, and the 4-byte overflow → `ProtocolError`). `encodeString` enforces the 65535 limit with byte-length `strlen`, not `mb_strlen` — a bug most implementations ship. `decodeString` bounds-checks before every `substr`, and every `unpack()` call guards the `array|false` return. Remaining Length, CONNECT flag bit placement (will-QoS at bits 3-4, will-retain 0x20, reserved bit clear), the `MQTT`/4 name and level, the SUBSCRIBE/UNSUBSCRIBE 0x02 reserved flags, the MQTT 5 SUBSCRIBE options byte (NL/RAP/Retain-Handling per §3.8.3.1), and the short-form ACK path (Remaining Length 2 → implicit success) are all spec-correct. Nothing anywhere claims MQIsdp/3. Four independent auditors probed this layer and none found a wire-format defect.

**`ReasonCode` is complete and well-modelled** — the full 0x00–0xA2 table with descriptions and a sensible `toException()` mapping. It is dead code today, but it is *correct* dead code: wiring it up closes six findings at once with no new design work.

**Partial writes are handled correctly in both transports** — both `write()` implementations loop until fully flushed. This is a common and nasty bug that this library does not have.

**TLS defaults are right at every construction path traced.** `Easy\Mqtt::publish(tls: true)` → `new TlsOptions()` with `verify_peer`/`verify_peer_name` true; the legacy array path in `Client::connect()` injects only `peer_name`; `TcpTransport::enableTls()` back-fills both verify flags when absent. A lot of PHP MQTT code gets this wrong by default. This one does not.

**The feature breadth is real and the leaf implementations are sound.** `FlowControl`, `TopicAliasManager`, `SharedSubscription`, `OfflineQueue`, `RateLimiter` (which already has `tryAcquire()`/`availableTokens()` for event-loop use), `FileSessionStore` — these are not stubs, and `FlowControlTest`, `TopicAliasManagerTest` and `SharedSubscriptionTest` are proper behavioural tests with negative cases, not coverage theatre. The gap is that `Client` does not call several of them, not that they are wrong.

**The `Protocol\` namespace is pure and reusable.** The sans-io split this roadmap recommends is *available*, not blocked — only `Client` hard-codes synchronous waits. That is a much better position than most libraries are in when they need to go async.

**Modern PHP is used where it is used.** `readonly` DTOs, PSR-3 and PSR-14 correctly wired, PHP 8.4 property hooks and `private(set)` in `TopicAliasManager`, typed class constants, `declare(strict_types=1)` everywhere. PHPStan at **max** with `treatPhpDocTypesAsCertain: true` and `checkMissingTypehints: true` at zero errors, 96.5% type coverage, Pint clean, Rector configured for 8.4 with deadCode/codeQuality/typeDeclarations/privatization/earlyReturn/strictBooleans. Six CI jobs with least-privilege workflow permissions (`contents: read` on CI, `{}` on release — genuinely better than most repos). Keep-a-Changelog, SECURITY.md, issue and PR templates, a working `docker-compose.yml` with a healthcheck.

**Fair summary:** this is a well-engineered *codec* wrapped in an under-engineered *client*, inside a distribution that has never been installed from scratch. The protocol work is more mature than everything around it.

## The three things standing between this and being the ecosystem standard

### 1. It cannot yet be trusted with a message.

Not "has edge cases" — actively loses data on the happy path. `array_shift` on a packet-ID-keyed map silently discards most QoS 1 traffic after 256 messages and after every reconnect (`Client.php:784`). The inbound queue grows forever under the library's own documented `run()` pattern (`:1136`). Inbound topic aliases turn every message after the first into `topic: ''` the moment a user enables a documented option (`:766`). PUBACK 0x87 is reported as success (`:533`), SUBACK 0x80 as a live subscription (`:650`), and a refused CONNACK as a connected client (`:335`). Keepalive is driven by inbound traffic so a subscriber gets dropped every 1.5×keepalive (`:756`), and a missing PINGRESP latches the ping flag forever so the client sits on a dead socket indefinitely (`:184`). Any one of these disqualifies a client for production IoT; there are seven, and they interact.

### 2. It cannot be tested — by the maintainer or by its users.

`Client.php` is 1296 lines holding twelve responsibilities with **zero unit tests**, because there is no injectable seam and no in-memory transport, in a repo where `TransportInterface` is six trivially-fakeable methods. Roughly 4,900 of ~9,100 `src/` lines have no direct test — and it is precisely the half that talks to a network. The 10 integration tests that would cover it self-skip on every CI run because the `docker-compose.yml` Mosquitto sitting in the repo is never started. The documented 85% type-coverage gate cannot fail (`tests/Pest.php:6` calls a function that does not exist; CI passes no `--min`). There is no line-coverage floor at all. That combination is how a 35-character WebSocket GUID, an `unset()` on a typed property, and an `array_shift` key reindex all shipped through a green build with PHPStan at max — and it is also why a downstream team cannot unit-test their own `TelemetryPublisher` without booting Docker. Shipping `Testing\InMemoryTransport` is ~60 lines and is the single highest-leverage change in this document.

### 3. It cannot be installed, adopted, or integrated.

`composer require` **fails outright** on stock `php:8.4-cli` for `ext-sockets`, an extension with zero call sites in the codebase. The README's flagship subscribe snippet silently subscribes to a topic named `Array`. Seventeen of twenty examples fatal on a fresh clone for a gitignored config file with no `.dist`. `.gitignore` is untracked because it ignores itself, so the project's own mTLS workflow can commit private keys. Five advertised features have no docs and no examples; the 487-line WebSocket transport has never completed a handshake against any compliant broker. And structurally: the library is blocking to the bone — `readExact()` has no readiness primitive and `usleep()` is hard-coded in `Client`, `RateLimiter` and the backoff path — so a ReactPHP/Amp/Octane adapter is not merely unwritten, it is **unexpressible**, which directly contradicts "the standard MQTT client for modern PHP." There is no Laravel service provider and no Symfony bundle, which is the concrete, unglamorous reason `php-mqtt/client` holds the default-choice slot with a weaker protocol layer.

**Sequencing recommendation:** Tier 0 is roughly two weeks of small, mostly two-line fixes and buys correctness. Tier 2.1 (`InMemoryTransport`) should be pulled *forward* into Tier 0 — write it first and use it to prove each Tier 0 fix. Tier 1 is the real deadline: do not cut a stable 1.0/2.0 tag until the property typing, the immutability enforcement, the result objects, the exception hierarchy and the transport contract are settled, because every one of them is free today and permanent afterwards. Tier 2 is where "competent client" becomes "reference implementation", and the order within it is `Testing\` → CI → Laravel bridge → async → docs site.
